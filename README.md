# Logdog Feishu

Logdog Feishu 在 Linux 上持续读取多个项目、服务和日志文件。日志命中关键字后，它会把项目、服务、文件路径和上下文发送到一个飞书群自定义机器人，减少人工查看日志的需要。

它不是飞书应用机器人，也不提供 Web 管理后台。一个进程只使用一个群机器人 Webhook。

## 开始使用

### 1. 创建飞书群机器人

在接收告警的飞书群中打开：

```text
群设置 -> 群机器人 -> 添加机器人 -> 自定义机器人
```

复制 Webhook；如果启用签名校验，同时复制签名密钥。两项只在服务器上的 TUI 中填写，不要提交到仓库或写入运行日志。

### 2. 生成配置

在程序目录运行：

```bash
./logdog-feishu configure
```

填写：

- `Webhook URL`：飞书群自定义机器人的地址。
- `Signing secret`：签名校验密钥，可留空。
- `Project`：项目名，例如 `shadouhui`。
- `Service`：服务名，例如 `gateway`；项目和服务组合必须唯一。
- `Paths`：日志绝对路径，多个路径用英文逗号分隔。
- `Include keywords`：触发告警的关键字，例如 `ERROR, FATAL, Exception`。
- `Exclude keywords`：不告警的关键字，可留空。
- `Scan seconds`：发现新文件的扫描间隔，通常填 `10`。

用方向键或 Tab 移动，在 `Save configuration` 上按回车保存，在 `Add service` 上按回车添加服务。配置会保存为当前目录的 `config.yaml`，权限为 `0600`。

### 3. 启动监听

先前台确认配置：

```bash
./logdog-feishu run
```

确认日志显示每个服务的 `watching` 和文件数量后，再使用 [systemd 原地部署说明](deploy/DEPLOY.md) 设置后台运行和开机自启。程序、配置和状态文件可以始终保留在解压目录。

## 路径和关键字

- 填写服务器上的绝对路径，建议不要使用 `~`、环境变量或相对路径。
- 填写目录时，程序监听该目录下的 `*.log`，不递归子目录。
- 文件和 glob 遵循 Go `filepath.Glob` 语义，不支持 `**`。
- 匹配区分大小写；排除关键字优先于包含关键字。
- 目录中的 `.log.gz` 不会被读取。需要监听其他后缀时，直接填写文件路径或 glob。
- 首次发现已有文件时从文件末尾开始，之后只读取新增内容。

常见初始关键字：

```text
ERROR, FATAL, panic:, Exception, Traceback, OutOfMemoryError
```

根据实际日志调整。`WARN` 往往噪声较多，建议确认内容后再加入。

## 告警报告

日志报告包含：

```text
项目、服务、主机、监听规则、监听目录、实际文件、文件身份、字节范围、时间、关键字、原始上下文
```

命中后会保留前置窗口并继续收集多行堆栈和后文。报告边界使用有限的时间戳、日志级别和缩进规则判断；无法确认时会标明完整性未知。单行、单份报告和飞书消息都有大小上限，超限会明确标记，不静默伪装成完整报告。长报告按 `Report` 编号和 `Part: n/m` 分段发送。

发送日志只记录报告编号、来源、分段、尝试、重试、成功或失败，不记录 Webhook、签名密钥或报告原文：

```bash
journalctl -u logdog-feishu -f -o cat
```

## 服务器资源告警

TUI 中选择 `Enable server monitoring` 后，程序可以监控当前 Linux 主机的平均负载和内存：

- 每 30 秒采样一次。
- 1 分钟平均负载除以 CPU 核数达到阈值，或内存使用率达到阈值，持续 3 分钟才告警。
- 同一指标 15 分钟内不重复告警。
- 默认阈值为每核负载 `1.0`、内存 `90%`，功能默认关闭。
- 资源报告与日志报告发送到同一个群机器人。

内存使用率按 `(MemTotal - MemAvailable) / MemTotal` 计算。资源采样异常会写入运行日志并重置持续计时，不会停止日志监听。

## 状态和恢复

默认在配置旁生成：

```text
config.yaml.state       游标和待发报告
config.yaml.state.lock  防止多个实例使用同一状态
```

游标按项目、服务、绝对文件路径和文件身份隔离。程序会处理日志追加、轮转、截断、删除和新文件发现。发送前会保存待发报告，发送成功后确认偏移；网络失败时下次启动会重试，可能重复发送，不承诺严格的 exactly-once。

不要删除 `.state` 文件来解决网络或告警问题，否则会失去续读位置和待发报告。

## 构建

```bash
go test ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o logdog-feishu .
```

生成 amd64 和 arm64 安装包：

```bash
bash script/build-linux.sh
```

服务器只需要对应架构的静态 Linux 二进制，不需要安装 Go。安装包、校验和及部署步骤见 [deploy/DEPLOY.md](deploy/DEPLOY.md)。

## 当前边界

程序依赖 Linux `/proc` 获取主机资源；不解析容器配额。上下文边界是启发式规则，不能识别所有日志格式。实际 Linux 长期运行、RSS 峰值和真实飞书群验收应在目标服务器上完成。
